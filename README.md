# Marketplace: интернет-магазин одежды на ASP.NET Core MVC

Учебный дипломный проект: веб-приложение интернет-магазина с каталогом, корзиной, личным кабинетом и админ-панелью.

> **Важно:** оплата и банковские карты в проекте **демонстрационные**. Реальные платежи не выполняются, не вводите настоящие данные карты. Все аккаунты и товары в проекте тестовые.

## Возможности

**Для покупателя**
- главная страница с популярными товарами;
- каталог с фильтром по категориям и подкатегориям (одежда, обувь, аксессуары);
- карточка товара: описание, состав, уход, доступные размеры, наличие на складе;
- корзина (хранится в сессии) с изменением количества и проверкой остатков;
- оформление заказа: остатки списываются и заказ создаётся в одной транзакции;
- регистрация и вход, личный кабинет, редактирование профиля, привязка (демо) банковских карт;
- история заказов.

**Для администратора**
- панель со статистикой (товары, заказы, пользователи, заказы и выручка за сегодня, общий остаток);
- добавление, редактирование и удаление товаров, загрузка изображений (проверка расширения, уникальные имена файлов);
- просмотр заказов и смена их статуса;
- список пользователей.

## Технологии

- C#, .NET 8, ASP.NET Core MVC (Razor)
- Entity Framework Core 8 + SQL Server (LocalDB)
- Cookie-аутентификация с ролями (`User`, `Admin`), хэширование паролей (`PasswordHasher`)
- Bootstrap, jQuery Validation

## Запуск

Нужно: [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и SQL Server LocalDB (идёт вместе с Visual Studio).

```bash
git clone https://github.com/Sinte643/Marketplace.git
cd Marketplace
dotnet run
```

Адрес приложения появится в консоли (по умолчанию `http://localhost:5169`). База данных `MarketplaceDB` создаётся автоматически при первом запуске и заполняется тестовыми товарами. Строка подключения находится в `appsettings.json`.

## Безопасность

- пароли хранятся в виде хэша (старые пароли открытым текстом автоматически заменяются хэшем при первом входе);
- вход и роли держатся на подписанной cookie аутентификации, а не на пользовательских значениях;
- админ-контроллер защищён атрибутом `[Authorize(Roles = "Admin")]`;
- для всех POST-запросов включена проверка антифальсификационного токена (CSRF);
- роль нельзя задать через форму регистрации, email уникален.
